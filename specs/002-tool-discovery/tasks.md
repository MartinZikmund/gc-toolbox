# Tasks: Attribute-Based Tool Auto-Discovery & Navigation Tree

**Input**: Design documents from `specs/002-tool-discovery/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/ (all present)

**Tests**: INCLUDED. The project's global conventions mandate TDD with MSTest, so test tasks are generated and (per TDD) authored before/alongside their implementation. The source generator is the heart of this feature; its output and diagnostics are covered by the Roslyn testing harness.

**Organization**: Tasks are grouped by user story (US1–US5 from spec.md). Because all discovery flows through **one** generator (`GcToolkit.SourceGenerators`) running against the app head, the stories are *incremental* on that generator rather than fully parallel — US1 stands up discovery; US2–US5 extend it. The generator file is a shared serialization point (edits to it are sequential, never `[P]`).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task)
- **[Story]**: US1–US5 (user-story phases only)
- Exact file paths are given. All paths are repo-relative from `D:\Personal\gc-toolbox\` (this worktree).

## Path conventions

- App head: `src/GcToolkit/`  ·  Shared library (all ViewModels + `[Tool]` types live here): `src/GcToolkit.Core/`
- Generator (netstandard2.0 analyzer, referenced by the app head): `src/GcToolkit.SourceGenerators/`
- Tests: `tests/GcToolkit.Core.Tests/`, `tests/GcToolkit.SourceGenerators.Tests/`

## Dependencies & Execution Order

### Phase dependencies

- **Setup (Phase 1)**: no dependencies.
- **Foundational (Phase 2)**: depends on Setup. **Blocks all user stories.**
- **User stories (Phases 3–7)**: all depend on Foundational. They are **incremental on the one generator**, so the realistic order is **US1 → US2 → US3 → US4 → US5** (see below), not free parallelism.
- **Polish (Phase 8)**: depends on the desired stories being complete.

### User-story dependencies (honest about coupling)

- **US1 (P1)** — stands up the generator (discovery + contributor + view registrations) and the stub tools. Everything else builds on it.
- **US2 (P1)** — depends on US1 (tools must be discovered to localize). Adds the `<Id>_Name`/`<Id>_Tooltip` resources + tooltip display.
- **US3 (P1)** — depends on US1 (extends the same generator with `NavigationTree`) and renders the pane.
- **US4 (P2)** — depends on US1 (dates are emitted by US1's generator) for the classifier/badge/section.
- **US5 (P2)** — depends on US1 (extends the generator with diagnostics) **and assumes US2's resources exist**, since `GCTOOL004` enforces them (and `WarningsAsErrors=True` makes any gap fatal). Run US5 after US2.

### Shared serialization points (NOT parallel)

- `src/GcToolkit.SourceGenerators/ToolDiscoveryGenerator.cs` — edited in T019, T020 (US1), T033 (US3), T045, T046 (US5). Sequential.
- `src/GcToolkit/Resources/DataTemplates.xaml` — T026 (US1), T030 (US2), T041 (US4). Sequential.
- `Strings/{en,cs}/Resources.resw` — T028/T029 (US2), T042 (US4). The EN and CS files are different files (so T028 ∥ T029), but later edits to the same file are sequential.

### Within each story

- Tests first (TDD), then implementation.
- Foundational types (Phase 2) before any generator/VM/UI work.
- Generator emission before the app-side consumption that depends on it.

## Implementation Strategy

### MVP first (User Story 1)

1. Phase 1 Setup → Phase 2 Foundational → Phase 3 US1.
2. **STOP and VALIDATE**: add/remove a `[Tool]` VM and watch it appear/disappear in the catalog and open via the shared host; confirm `PlaceholderToolContributor` is gone (SC-006). This is the headline of issue #71.

### Incremental delivery

1. Foundation ready → **US1** (discovery MVP) → demo.
2. **US2** (localized names/tooltips) → the P1 catalog is fully usable.
3. **US3** (navigation pane) → the headline user-visible payoff; P1 complete.
4. **US4** (New & Updated) → P2 additive.
5. **US5** (build-time validation) → P2; locks in correctness once resources (US2) exist.

### Notes

- `[P]` = different files, no dependency on an incomplete task.
- The generator runs only in the app-head build; inspect emitted code under `src/GcToolkit/obj/.../generated/` when diagnosing `GCTOOL###`.
- Tool-attribute diagnostics are location-less by design (research R2) — keep messages identifying (`type` + `Id`).
- Commit after each task or logical group; stop at any checkpoint to validate a story independently.
